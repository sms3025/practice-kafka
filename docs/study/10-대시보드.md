# 10. 대시보드: Grafana 패널 하나 = SQL 한 줄

명세서는 자체 대시보드를 필수로, Grafana를 운영 보조로 둔다. 이 장의 목적은 둘이다. ClickHouse에 로그가 제대로 들어갔는지 화면으로 확인하는 것, 그리고 나중에 자체 대시보드를 만들 때 "어떤 쿼리로 어떤 그래프를 그리는가"의 견본을 얻는 것이다. Grafana 패널 하나는 결국 SQL 한 줄과 그림 종류의 조합이다. 도구 소개는 `../concepts/03-주변-도구.md`, 따라 하는 절차는 `../practice/07-ClickHouse-적재.md` H8이다.

## 1. 손으로 만들지 않고 파일로 넣는다

Grafana는 화면에서 데이터 소스와 대시보드를 만들 수 있지만, 그러면 컨테이너를 지울 때 같이 사라지고 다른 사람이 같은 화면을 얻을 수 없다. 그래서 파일로 넣는다(provisioning). compose가 세 가지를 마운트한다.

| 파일 | 하는 일 |
|---|---|
| `docker/grafana/provisioning/datasources/clickhouse.yml` | ClickHouse 데이터 소스. 주소 `clickhouse:8123`(docker 네트워크 안의 이름), 사용자 `app` |
| `docker/grafana/provisioning/dashboards/dashboards.yml` | 아래 폴더의 JSON을 대시보드로 올린다 |
| `docker/grafana/dashboards/logs.json` | 대시보드 "장비 로그 (ClickHouse)" |

ClickHouse 데이터 소스는 Grafana에 기본으로 들어 있지 않은 플러그인이다. compose의 `GF_INSTALL_PLUGINS: grafana-clickhouse-datasource`가 첫 기동 때 인터넷에서 받는다. 망분리 환경에서는 이 플러그인 파일을 미리 넣어야 한다는 점을 기업 프로젝트에서 기억해 둔다.

화면은 http://localhost:3000 이다. 로그인하지 않아도 보기 권한으로 열리고, 고치려면 `admin`/`admin`으로 들어간다. 다만 이 대시보드는 파일이 원본이라 화면에서 고친 것은 저장되지 않는다(`allowUiUpdates: false`). 바꾸려면 JSON을 고치고 Grafana를 재시작한다.

## 2. 패널 다섯 개와 그 쿼리

`$__timeFilter(컬럼)`과 `$__timeInterval(컬럼)`은 ClickHouse 플러그인의 매크로다. 화면 오른쪽 위에서 고른 기간과 그래프 폭에 맞는 묶음 간격으로 바뀐다.

**레벨별 로그 수.** 이벤트 시각을 간격별로 묶어 레벨마다 센다. 결과는 (시각, 레벨, 건수)의 긴 표인데, 형식을 시계열로 두면 플러그인이 레벨마다 선 하나로 나눠 준다.

```sql
SELECT $__timeInterval(event_time) AS time, ifNull(level, 'NONE') AS level, count() AS logs
FROM logs.app_logs WHERE $__timeFilter(event_time)
GROUP BY time, level ORDER BY time
```

**ERROR가 많은 장비 상위 10.** 장애 장비를 찾는 가장 단순한 화면이다. 정렬 키 첫 컬럼이 `device_id`라 장비별 집계가 빠르다.

```sql
SELECT device_id, count() AS errors FROM logs.app_logs
WHERE $__timeFilter(event_time) AND level = 'ERROR'
GROUP BY device_id ORDER BY errors DESC LIMIT 10
```

**수집 → 저장 지연.** 09장의 `inserted_at - collected_at`을 저장된 시각 기준으로 그린다. 파이프라인 어딘가가 밀리면 이 선이 먼저 오른다. lag와 함께 보는 운영 지표다.

```sql
SELECT $__timeInterval(inserted_at) AS time,
       quantile(0.5)(dateDiff('millisecond', collected_at, inserted_at)) AS p50,
       quantile(0.99)(dateDiff('millisecond', collected_at, inserted_at)) AS p99
FROM logs.app_logs WHERE $__timeFilter(inserted_at) GROUP BY time ORDER BY time
```

**최근 ERROR 100건**과 **저장된 행 수**는 표와 숫자 하나다. 행 수는 `count()`라서 병합 전 중복을 포함한다(09장 2절). 정확한 수가 필요한 화면이 아니므로 `FINAL`을 붙이지 않았다. `FINAL`은 읽을 때 중복을 접느라 느려진다.

2026-10-19에 다섯 패널의 쿼리를 Grafana API(`/api/ds/query`)로 그대로 실행해 모두 데이터를 돌려받는 것을 확인했다. 레벨별 패널은 레벨 다섯 개가 각각의 계열로, 상위 10 패널은 장비 10개, 최근 ERROR는 100행이 나왔다.

## 3. 시각 이야기

대시보드의 기본 기간은 최근 30일이다. 대외비 생성기 로그는 생성한 날짜(이 저장소의 사본은 2026-10-07)에 찍혀 있어, 기간을 짧게 잡으면 보이지 않는다. 시뮬레이터(`/api/logs/simulate`)로 만든 로그는 지금 시각이라 최근 몇 분에 보인다.

ClickHouse에는 UTC로 저장되고, Grafana는 브라우저의 시간대(한국)로 바꿔 그린다. 그래서 화면의 14시는 저장된 값으로는 05시다. 자체 대시보드를 만들 때도 저장은 UTC, 표시는 사용자 시간대라는 규칙을 그대로 따른다.
