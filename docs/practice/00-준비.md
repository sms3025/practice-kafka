# 00. 준비: 도구 확인과 깨끗한 출발점

실습에 들어가기 전에 세 가지를 맞춘다. 도구가 실제로 실행되는지 확인하고, 터미널에서 Gradle을 돌릴 수 있게 하고, 이전 실험의 흔적을 지운다. 세 번째를 건너뛰면 B4(재시작 후 오프셋)나 D1(수신 건수)의 숫자가 문서와 달라져 헷갈린다.

## 0-1. Docker Desktop

**왜 하는가.** Kafka, Kafka UI, Fluent Bit은 모두 docker 컨테이너로 뜬다. Docker Desktop이 꺼져 있으면 모든 docker 명령이 실패한다.

**할 것.**

1. 작업 표시줄 오른쪽에 고래 아이콘이 있는지 본다. 없으면 시작 메뉴에서 Docker Desktop을 실행하고 "Engine running"이 될 때까지 기다린다.
2. 명령 터미널에서 친다.

```powershell
docker version --format '{{.Server.Version}}'
docker compose version
```

**보여야 하는 것.** 첫 줄에 서버 버전 숫자, 둘째 줄에 `Docker Compose version v2.x`.

**안 될 때.** `error during connect`나 `The system cannot find the file specified`가 나오면 Docker Desktop 엔진이 아직 안 떴다. 1분 기다렸다가 다시 친다.

## 0-2. 터미널에서 Gradle 돌리기

**왜 하는가.** 이 PC의 PATH에는 Java가 없다. `gradlew.bat`은 Gradle 자체를 띄우는 데 JDK가 하나 필요하므로 `JAVA_HOME`을 잡아 줘야 한다. IntelliJ에 내장된 JDK(JBR 25)를 쓴다. 프로젝트를 컴파일하고 실행하는 JDK 25는 Gradle 툴체인이 따로 관리하므로 신경 쓰지 않아도 된다.

**할 것.**

1. IntelliJ에서 프로젝트를 연다. 오른쪽 아래 진행 표시줄의 Gradle import가 끝날 때까지 기다린다.
2. Terminal 탭(명령 터미널)에서 친다.

```powershell
$env:JAVA_HOME = "C:\Program Files\JetBrains\IntelliJ IDEA 2026.1.4\jbr"
.\gradlew.bat test
```

**보여야 하는 것.** 1분 안팎 뒤 마지막에 `BUILD SUCCESSFUL`. 이 테스트는 docker가 없어도 돈다. `LogNormalizerTest`는 순수 단위 테스트이고, 통합 테스트는 `@EmbeddedKafka`가 JVM 안에 임시 브로커를 띄워 쓰기 때문이다.

**안 될 때.** `JAVA_HOME is not set`이 나오면 첫 줄을 빠뜨렸거나 다른 터미널 탭에서 친 것이다. `$env:JAVA_HOME`은 **그 터미널 탭에서만** 유효하다. 탭을 새로 열면 다시 쳐야 한다. 매번 치기 싫으면 아래를 한 번 실행하고 IntelliJ를 재시작한다(사용자 환경 변수에 영구 저장).

```powershell
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\JetBrains\IntelliJ IDEA 2026.1.4\jbr", "User")
```

IntelliJ를 업데이트해 설치 폴더 이름(`2026.1.4`)이 바뀌면 경로도 바꾼다.

## 0-3. IntelliJ 실행 구성 확인

**왜 하는가.** 앱은 IntelliJ에서 띄우는 것이 가장 편하다. 콘솔이 Run 창에 따로 나오고 재시작이 버튼 하나다. 다만 연습용 로그 경로 `app.simulator.dir=docker/devices/sim`이 상대 경로라 실행 위치(Working directory)가 프로젝트 루트여야 한다.

**할 것.**

1. `src/main/java/com/practice/kafka/PracticeKafkaApplication.java`를 연다. `main` 왼쪽의 초록 실행 버튼을 오른쪽 클릭 → Modify Run Configuration.
2. Working directory가 프로젝트 폴더(`...\practice-kafka`)인지 본다. 다르면 고친다. 저장만 하고 **아직 실행하지 않는다.** Kafka가 없으면 앱이 접속 경고를 계속 찍는다. 실행은 02 파일의 B1에서 한다.

터미널을 선호하면 IntelliJ 대신 터미널 탭을 하나 더 열고 `.\gradlew.bat bootRun`으로 띄워도 된다(0-2의 `JAVA_HOME` 필요). 끌 때는 그 탭에서 Ctrl+C를 누른다. 이 안내에서 "앱을 켠다/끈다/재시작한다"는 둘 중 어느 방법이든 같은 뜻이다.

## 0-4. 이전 흔적 지우기

**왜 하는가.** 이 PC에는 이미 `app-logs` 토픽과 `log-printer` 컨슈머 그룹이 있고, 메시지가 수천 건 들어 있다(2026-10-14~15 검증 실행 때 보낸 것 포함). `docker/devices/sim`에도 연습용 로그 파일이 남아 있다. 이 상태에서 시작하면 "처음 붙은 컨슈머가 처음부터 읽는다", "200줄 쓰면 200건 받는다" 같은 기대 결과가 어긋난다.

**할 것.** 앱이 떠 있으면 먼저 끄고, `README.md` 6절의 네 단계를 그대로 친다.

```powershell
docker compose -f docker/docker-compose.yml down -v
Remove-Item -Recurse -Force docker\devices\sim, docker\devices\OHT-* -ErrorAction SilentlyContinue
```

다시 띄우는 `up -d`는 01 파일 A1에서 하므로 여기서는 지우기만 한다.

**보여야 하는 것.** `down -v`가 컨테이너 셋(kafka, kafka-ui, fluent-bit), 네트워크 하나, 볼륨 셋(kafka-data, fluent-bit-state, fluent-bit-storage)을 `Removed`로 찍는다. `Get-ChildItem docker\devices -Force`를 치면 `.gitkeep`만 남아 있다.

## 0-5. (E절을 할 사람만) Python

**왜 하는가.** OHT 로그 생성기는 Python 프로그램이다. 이 PC에서 `python`을 치면 진짜 Python이 아니라 Microsoft Store 바로가기가 잡혀 `Python was not found; run without arguments to install from the Microsoft Store`가 나온다(2026-10-15 확인).

**할 것.** E절 직전에 해도 된다.

1. https://www.python.org/downloads/ 에서 3.8 이상을 내려받아 설치한다. 설치 첫 화면에서 "Add python.exe to PATH"를 체크한다. 또는 터미널에서 `winget install Python.Python.3.12`를 친다.
2. Windows 설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭에서 `python.exe`, `python3.exe`의 "앱 설치 관리자" 항목을 끈다. 안 끄면 Store 바로가기가 계속 먼저 잡힌다.
3. 터미널을 새로 열고 `python --version`을 친다. `Python 3.x.y`가 나오면 된다.
